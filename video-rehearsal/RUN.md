# Delivery rehearsal: synthetic fixture

A fixed six-second test pattern and tone, not a general-purpose product checker. No model provider or paid generation is used. Python 3.12.3, Playwright 1.64.1, imageio-ffmpeg 0.8.1 and headless Chromium 156.0.8078.4 were used for the recorded run on Linux ARM64.

## Setup and run

From this directory, create a virtual environment and install the two dependencies:

```sh
python3 -m venv .venv
.venv/bin/pip install playwright==1.64.1 imageio-ffmpeg==0.8.1
.venv/bin/python -m playwright install chromium
```

Installation is not proof the browser launches. On Linux additional system libraries may be required; stop and record the blocker rather than silently installing privileged packages. An existing Playwright browser installation can be selected with `PLAYWRIGHT_BROWSERS_PATH`. An existing FFmpeg can be selected with `FFMPEG_BIN`; otherwise the script uses FFmpeg on PATH or imageio-ffmpeg.

Run the working route, then the deliberately limited server and diagnosis:

```sh
REHEARSAL_SERVER=range REHEARSAL_OUTPUT=run-range .venv/bin/python playback_trial.py
REHEARSAL_SERVER=simple REHEARSAL_OUTPUT=run-simple .venv/bin/python playback_trial.py
REHEARSAL_OUTPUT=run-simple .venv/bin/python seek_diagnosis.py
```

Each output directory is generated/overwritten by its run. Use a fresh directory when preserving earlier evidence. Do not point at an existing production package: these scripts generate their own synthetic fixtures. The default output is `playback-trial/` beside the scripts.

`playback_trial.py` produces `good/`, `broken/` (missing VTT), `fixture.zip`, an extracted good copy, caption-on/off screenshots, and `results.json`. Both MP4 and WebM are forced separately; this does not test automatic source fallback. Its exit code 0 means execution completed, NOT that viewing passed: inspect every row. Expected negative cases remain explicit false values. Browser launch failure records `status: not tested`, a prerequisite-failure reason, and exits 2; dependent viewing checks have not run. Other setup failures raise an error and must not be counted as passes.

`seek_diagnosis.py` requires those generated files. It compares identical WebM bytes under simple HTTP, range-capable HTTP and direct-file viewing, plus a front-cues remux. It repeats each condition twice and retains response statuses, console errors, seek position and active caption text in `seek-diagnosis.json`.

For a manual viewing route using the generated bytes:

```sh
.venv/bin/python fixture_server.py run-range --port 8765
```

Open `http://127.0.0.1:8765/good/index.html` and the corresponding `broken/index.html`. Enable captions if needed. Stop the server with Ctrl-C. This local fixture server binds only to loopback, supports the single byte ranges used by these tests, reads small fixture files into memory, and is not production hosting software. Do not use browser security-bypass flags.

## Expected observations for the recorded browser

| Delivery | MP4 picture/seek | WebM picture/seek | Good captions | Missing-caption variant |
|---|---|---|---|---|
| Range HTTP | pass / pass | pass / pass | pass | video passes; captions fail |
| Simple HTTP | pass / pass | pass / fail (returns to 0s) | pass | video passes; captions fail |
| Direct file (WebM diagnosis only) | not tested | playback reaches >1s / seek passes | fail: external VTT blocked | not tested |

The original and ZIP-extracted good copies match under each HTTP route. That is NOT a pass for double-click offline viewing. The file-origin diagnosis opens the generated good viewer by URL, not through a desktop file manager.
